# Phase 3: Requirements and uncertainty

Turn confirmed answers into functional and non-functional requirements, use cases or user stories, business rules, acceptance criteria, dependencies, constraints, and out-of-scope items. Give important requirements stable `REQ-####` IDs. Each one gets a claim label and a requirement status, as defined in `${CLAUDE_PLUGIN_ROOT}/policies/evidence.md`, plus a link to its source.

Look for contradictions, missing actors, conflicting acceptance criteria, and incompatible constraints. Present each conflict with its options and ask the user to resolve the material ones. Keep the record small and grow it as discovery proceeds.

Record in `docs/product/requirements.md`, using `${CLAUDE_PLUGIN_ROOT}/templates/requirements.md` as the structure. Then assess checkpoint A with the `simple-eng:checkpoints` skill.
