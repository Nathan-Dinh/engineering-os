# Technology selection

Do not recommend a technology for popularity, familiarity, or trend alone. For a consequential choice:

1. Restate the requirements, constraints, top quality attributes, and unknowns that affect it.
2. Check the existing stack and team skills. In an existing project, keep established technologies unless there is a justified case for change.
3. Present two or three viable alternatives only when a real choice exists. Do not invent options to fill a quota.
4. Compare fit, development velocity, ecosystem maturity, operational complexity, security, hosting constraints, lifecycle, and cost against this project's drivers.
5. State the evidence and its limits. Cite a current source for any vendor capability or price.
6. Recommend a default and explain the trade-offs. Keep it proposed until the decision owner approves.
7. Record the choice as a DEC with alternatives, evidence, and consequences.

Evaluate only the categories that apply: language, frontend and backend frameworks, database and data access, authentication, hosting and deployment, CI/CD, testing, monitoring, and infrastructure provisioning. Add a component only for a demonstrated requirement.
