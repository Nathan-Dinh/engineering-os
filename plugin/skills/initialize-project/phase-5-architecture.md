# Phase 5: Architecture and technology

Start only once requirements and the major quality drivers are understood. Then work out which capabilities the requirements actually call for: client platforms, APIs, background work, real-time needs, integrations, object storage, search, caching, queues, authentication and authorization, and observability. Include a component only when a requirement supports it.

For the architecture and any meaningful technology choice, invoke the `simple-eng:architecture-design` skill. It handles C4 views, alternatives, and DEC proposals. Keep each recommendation separate from an accepted choice, and do not adopt a consequential choice before the decision owner approves it.
