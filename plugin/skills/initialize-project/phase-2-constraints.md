# Phase 2: Constraints and risk

Ask about budget, timeline, team skills and capacity, legal, privacy, regulatory, and contractual constraints, integrations, hosting, and data sensitivity. Ask who may approve consequential decisions. Follow up only where an answer changes feasibility, authorization, or architecture.

A constraint is confirmed only when the user confirms it or evidence verifies it. Flag conflicts (for example, scope against timeline), explain the options, and let the user choose; do not resolve them silently.

Record in `docs/PROJECT.md`: "Constraints" and "Decision owners".
